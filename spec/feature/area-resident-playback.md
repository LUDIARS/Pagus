# エリア購読による住民再生

## 責務

- BT・LLM介入の採否・経路探索・座標更新は既存のバックエンドで実行する。購読者の有無によってシミュレーションを止めない。
- `town-areas.ts` は一つの街を3×3の配信区画へ分割する。境界は各軸のグリッドサイズの三等分で、住民の確定座標から所属を決める。
- `area-stream.ts` は確定したWorldから対象区画の生存・公開済み住民とアイテムを抽出する。購読は読み取り専用でゲーム状態を変更しない。
- `AreaView` は区画選択と再接続時の再購読を扱う。区画名には公開・生存住民の人数を添え、最初の人口ありsnapshotだけ最多区画を自動選択する。以後は「住民のいる場所へ」を押した時だけ再探索し、視聴者の選択を勝手に追尾しない。
- `StageView` は入力を2系統に分ける: `update(world)` が全体snapshotで景観・建物ラベル・物語・話者名を更新し、`updateArea(frame.world)` が区画内住民のメッシュ・ラベル・経路補間だけを担う。裁判時もフロントで住民を広場へ移動させない。
- カメラは常に購読中の区画を写す。`resetCamera()` が中心・倍率2.5・yawを与え、ホーム操作・区画切替・初回snapshotがこれを呼ぶ。裁判の開始・終了でカメラを動かさない (購読先と表示先が食い違うため)。

## 配信契約

- client → server: `subscribeArea { area }`。接続ごとに1区画、初期購読はplazaで、最初の人口ありsnapshot受信後に最多区画へ切り替える。不正な区画名は採用しない。
- server → client: `areaFrame { area, sequence, world }`。毎回全置換であり、退場・死亡した住民をクライアントに残さない。区画切替時は最新フレームを即送信する。
- 再接続でsequenceの受理状態をリセットする。別区画または同一sequence以下のフレームは再生しない。エリア切替では旧住民のGPU資源・ラベル・経路を破棄する。
- サーバーは配信時のWorldを複製して保持し、エリア切替の瞬間にシミュレーション途中の状態を混ぜない。同一更新・同一区画のJSONは接続間で共有する。
- 送信待ちが1MiBを超えた接続にはsnapshot/areaFrameを追加せず、次の完全フレームで復帰する。ゲーム進行は接続に依存しない。

## 街全体の情報

既存の住民一覧・介入・裁判・統計パネルは街全体のsnapshotを利用する。互換性のため住民名簿（確定座標を含む）は引き続き全体配信し、移動経路はareaFrameだけに含める。3D画面は全体snapshotから住民を再生しない。名簿の差分配信や個別詳細取得はこの変更には含めない。

`areaFrame` は `residentHistory` / `relationships` / `userFaith` / `villagerActionLog` を空にするため、それらに依存する表示は必ず全体snapshot側で解決する。具体的には建物の在籍・就業者数 (`TownLabels`)、住民名のバッジ (`villagerDisplayName` → `residentHistory`)、裁判の話者名解決、周辺行動ログ、物語パネルが該当する。区画内アイテムだけは `areaFrame` 由来を描画する。
