# コスト削減リデザイン (v1.0) — LLM 呼び出しを「事件・裁判・操作」に限定する

> 2026-06-27 起草。ユーザ口述設計を正本化。SPEC.md §12 の実装索引。
> **本リデザインは PR #1〜#8 が実装した「毎セグメント LLM で全住民を思考させる」中核を置き換える。**
> 数値 (カルマ消費量・蓄積レート・イベント発火確率) は当て推量で、観戦して env で調整する前提。

## 0. 狙い — なぜ変えるか

現行 (§4.2 / §5.1) は **起の各セグメントで awake な住民 (代表) ごとに `Brain.decideAction` を LLM で呼ぶ**。
1 日 = 12 セグメント、1 ゲーム月 = 約 30 日なので、日常だけで LLM 呼び出しが毎分オーダーで走り、コストが青天井になる。

**方針: 日常から LLM を完全に外す。LLM を呼ぶのは「事件のデザイン」「事件用キャラ生成」「事件中の当事者応答」「裁判」だけにする。**
これにより steady-state の LLM コストは **「ゲーム内1か月 = 実1時間あたり 概ね 1 事件分」** + プレイヤーが起こした制裁/扇動裁判の分、に圧縮される。

## 1. LLM 呼び出し予算 (どこで呼ぶか / 呼ばないか)

| タイミング | LLM | 用途 | 頻度 |
|---|---|---|---|
| **月初** | ✅ | その月の事件の**発生日時を決める** (+ 大まかな種/テーマ) | ゲーム月1回 = 実1日1回 |
| **事件発生の前日** | ✅ | 前日の村の様子を見て**事件を詳細デザイン** + **事件用キャラを生成** | ゲーム月1回 |
| **事件発生中 (承)** | ✅ | 当事者キャラの応答 (GANs/Di 方式)。**各プレイヤーの介入に個別対応** | 事件ごと・有限 |
| **裁判 (転)** | ✅ | 糾弾・審議・判決ロジック | 事件/制裁ごと |
| **プレイヤー扇動由来の事件** | ✅ | 扇動で誘発された事件のデザイン/応答 | 操作ごと |
| **プレイヤー制裁由来の裁判** | ✅ | 制裁対象のつるし上げ裁判 | 操作ごと |
| 起の日常行動 (毎セグメント) | ❌ | **BT/ブラックボックスエンジン**で生成 | — |
| 感情更新 (毎 tick) | ❌ | アルゴリズムで変異 (§4) | — |
| 日末の世界評価 | ❌ | **アルゴリズム化** (現行 `WorldBrain.evaluateDay` の LLM 呼びを外す) | — |
| 祝日イベント | ❌ | アルゴリズム化 (定型テンプレ) | — |

> **無言フォールバック禁止 (RULE_CODE §7.1) は維持**: LLM モードで起動して事件デザイン用 backend が未設定なら即エラー。
> 「LLM を呼ばない」のは設計上の省略であって、設定不備の握りつぶしではない。

## 2. 日常 = BT / ブラックボックスエンジン (LLM 不使用)

現行の `kishoTick → Brain.decideAction` (LLM/住民1体ずつ) を、**LLM を挟まない行動エンジン**に置き換える。

- **行動の決定主体**: Behavior Tree もしくはブラックボックス (ルール/重み表) エンジン。
  - 既存の `EventDirector` (グループ代表 × カテゴリクォータ) はこのエンジンの母体として残し、`decideAction` の LLM 呼びだけを**決定的アクション生成**に差し替える。
  - アクション文 (「ベルが井戸端で愚痴った」等) は LLM ではなくテンプレ/語彙テーブルから組む。
- **感情** (現行 §3.1 で「感情=AI」) は **アルゴリズム変異**へ降格: 環境・直近イベント・性格から決定的に揺らす。
  - ※ §3.1 の「環境=プログラム / 感情=AI / 情報=蓄積」三分のうち、**感情の決定主体を AI→プログラムに変更**する (本リデザインの破壊的変更点)。
- **村のパラメータは日々変異しうる**: 住民の気質6軸・村の徳目6軸は、日常イベントの集計でアルゴリズム的に毎日少し動く (LLM 不使用)。

## 3. 事件 (Incident) のライフサイクル

### 3.1 月初: 発生日時のスケジューリング (LLM 1 回)

- ゲーム内月の開始 (`advanceDay` の `monthRolled`) で、**世界側 LLM がその月の事件発生日を 1 つ決める** (`WorldBrain.scheduleMonthlyIncident`)。
  - 入力: 村の評判・住民概況・村のルール (§9)。出力: `{ dayOfMonth, themeSeed }` (テーマは大まかな種だけ)。
- 決定は `world.scheduledIncident = { dayOfMonth, themeSeed, designed: false }` として永続化。

### 3.2 事件前日: 詳細デザイン + 事件用キャラ生成 (LLM 1 回)

- スケジュール日の**前日の日末**に、世界側 LLM が**前日時点の村の様子**を入力に事件を詳細化する (`WorldBrain.designIncident`)。
  - 出力: 事件の筋書き (description)、巻き込む既存住民、**新規生成する「事件用キャラ」**の有無と仕様。
- **事件用キャラ生成** (§3.3): 「露出狂が現れた」→露出狂キャラ、「殺人が起きる」→吃人犯 (殺人犯) キャラ、のように事件に応じた専用住民を 1 体以上 LLM 生成し村に投入する。

### 3.3 事件用キャラ (Incident Character)

- 事件のために LLM が生成し村に追加される住民。通常の `Villager` スキーマに乗る (`origin: 'incident'` で区別)。
- **賢い犯人は居座って連続犯になりうる**: 例えば殺人犯が**誰かに罪を擦り付けて (scapegoat) 村に留まり、事件を起こし続ける**筋書きを LLM が選べる。
  - → 裁判で別の住民が誤って処断され、真犯人 (事件用キャラ) が `alive` のまま残る経路を許容する。
  - 真犯人が残った場合、翌月以降の事件デザインの入力にその存在を渡し、連続性を持たせる。

### 3.4 事件中 (承): 当事者の LLM 応答 (Di 方式)

- 事件が発火している間、**当事者キャラ (加害者/被害者/事件用キャラ) は LLM 脳で応答**する。
- **各プレイヤーの介入に個別対応する**ために LLM が要る (= Discutere の対話エージェントと同型)。裁判も含めて Di と同様の仕掛け。
- 当事者以外の一般住民は LLM を持たない (日常エンジンのまま)。

## 4. プレイヤー操作の刷新 — 沈静化廃止 / 制裁新設 / 扇動改修

### 4.1 沈静化 (calm) を廃止

- `cmd.calm` / `TermLoop.calm` / `nudgeCalm` / 中央「無罪 NOT GUILTY」ボタンの沈静化効果を**削除**。
- 理由: 住民は放っておくと沈静化方向に向かう (§2 の BT は平穏に収束しやすい) ので、プレイヤーが沈静化させる操作は不要。プレイヤーの仕事は**波風を立てる**側に寄せる。

### 4.2 扇動 (incite) を改修 — 対象指定 + カルマ消費

- **キャラクター1体を対象に**、**カルマ**を消費して実行するコマンドにする (`cmd.incite { targetId }`)。
- 住民は沈静化に向かいがちなので、**扇動で事件を起こすようプレイヤーが誘導**できる意図。
- **仕掛けの文言** (§6 由来): 「○○がお前の悪口を言っていたぞ」のように、対象に偽の情報を吹き込む形で発火させられる (`incite { targetId, rumorAboutId }`)。
  - 情報 (§3.1「情報=蓄積」) に偽の `InfoItem` を注入し、対象の日常エンジンが事件化しやすくなる。

### 4.3 制裁 (sanction) を新設 — 特定人物のつるし上げ

- **特定の人物を対象**に実行 (`cmd.sanction { targetId }`)。扇動より**カルマを多く消費**。
- 制裁対象になった人物は**その日必ず裁判でつるし上げられる** (即時 `ten` を開く。被告は対象に固定 = `foolish` 段階をスキップ)。
- **裁判の選択肢が「死刑」「教育」の2択**になる (§5)。
  - 「死刑」票多数 → キャラクター消滅 (`alive=false`)。
  - 「教育」票多数 → 住民改変 (§3.3 既存 reform)。
- **どんなに善性の高いプレイヤーでも制裁できる。ただし善性に応じてカルマが多く必要** (§4.4 のプレイヤー善性)。

### 4.4 カルマ & プレイヤー善性

- **カルマは自動でたまる** (時間経過で `+rate/sec`、`PAGUS_KARMA_RATE`)。扇動/制裁で消費。制裁 > 扇動。
- **プレイヤー善性 (virtue)**: 応援 (§4.5) 等で上がるプレイヤー側のパラメータ。
  - 制裁の必要カルマは**善性に比例して増える** (`sanctionCost = base × (1 + virtue × k)`) — 善人ほど残酷な制裁の代償が重い。
- 多人数観戦のため、カルマ/善性は **userId ごと**に持つ (通知投票 §4.8 と同じ席管理)。

### 4.5 応援 (cheer) — 住民の後押し

- 住民を**応援できる** (`cmd.cheer { targetId }`)。**インターバル3分**、**ログに残る** (人間の行動記録 §9)。
- 応援された住民は**パラメータが1つ上がる** (気質6軸のいずれか + 関連する村の徳目)。
- 応援はプレイヤー善性を上げる (制裁を重くする裏返し)。

## 5. 裁判の簡素化 — 死刑 / 教育の2択

- 制裁由来・事件由来いずれの裁判も、最終投票を**「死刑」「教育」の2択**に統一する。
  - 現行の `fate` 段階 (`kill`/`spare`) を **`death`/`educate`** に置換 (`spare`→そのまま生かすではなく「教育で作り替える」)。
- 制裁裁判は被告が固定なので `foolish` (誰が愚かか) 段階を飛ばす。月次事件裁判は犯人特定が要る場合のみ `foolish` を残す。
- 投票合算は現行どおり (住民 bloc + userId ごと 1 席 + 狂人加重)。狂人の扇動 (§8B.1) は維持。

## 6. イベント由来パラメータ + アルゴリズムイベント (point 7)

- **イベント発生時に、内容に応じて住民パラメータを増やす**。例: 「殺人事件が起きた時の反応」パラメータ。
  - 住民に `eventParams: Record<string, number>` (タグ付きカウンタ) を持たせ、事件種別ごとに加算する。
- **このパラメータを使って普段のイベントが発火する** = 日常 BT/ブラックボックスの発火条件にイベント由来パラメータを組み込む (**アルゴリズムイベント**)。
  - 例: 「殺人を見た」反応値が高い住民は、日常で警戒/萎縮イベントを起こしやすくなる。
- **定期的に人間がレビューしてパラメータを消す** (`状態`/履歴パネルから手動クリア。膨張防止)。

## 7. 状態パネル (point 8)

- 新規 UI パネル「状態」。表示項目:
  - **LLM 使用コストログ**: 呼び出しごとの用途/モデル/トークン/概算コスト + 累積 (`server/llm/cost-log.ts`)。
  - **稼働開始時刻** (いつから動いているか)。
  - **今ゲーム内何年目か** + 現在の年月日・経過ターム。
- コストログは LLM クライアント (`cli-llm-client.ts`) で各呼び出しを計上し、WS (`status` メッセージ) で配信。

## 8. 村の歴史ページの詳細化 (point 9)

現行の `Chronicle` (節目の年代記) を**多面ページ**に拡張する。サブビュー:

| サブビュー | 内容 |
|---|---|
| **直近の事件ハイライト** | 最近の大事件の要約カード |
| **事件リスト** | 全事件の一覧 (日付・当事者・結末) |
| **住民リスト** | 現住民 + 退場者。気質/改変回数/事件関与 |
| **教育の歴史** | 改変 (reform) のログ (§8B.7 のいじられ方を時系列で) |
| **村のルール** | 村のしきたり (§8.1) |
| **人間の行動記録** | プレイヤーの扇動/制裁/応援の操作ログ (userId・対象・日時) |

### 8.1 村のルール (Village Rules) — 事件の火種

- 村の**しきたり**的なもの。**適当に用意され (生成テンプレ or LLM 種)、事件の火種になる**。
  - 例: 「夜に口笛を吹いてはならない」「梟は井戸に近づくな」。
- 事件デザイン (§3.2) の入力に村のルールを渡し、ルール違反を火種にした事件を作れるようにする。
- `world.villageRules: VillageRule[]` で保持・永続化。`村のルール` ビューで一覧。

## 9. 既存実装への影響 (破壊的変更の一覧)

| 既存 (#1〜#8) | 本リデザイン後 |
|---|---|
| 起 = 毎セグメント `Brain.decideAction` (LLM) | BT/ブラックボックス (LLM 不使用) §2 |
| 感情 = AI 更新 | アルゴリズム変異 §2 |
| 事件 = 嫌がらせ行動から自然発火 | 月初スケジュール + 前日 LLM デザイン §3 / 扇動誘発 §4.2 |
| 日末 = `WorldBrain.evaluateDay` (LLM) | アルゴリズム集計 §1 |
| 祝日 = `WorldBrain.holidayEvent` (LLM) | 定型テンプレ §1 |
| 沈静化コマンド | 廃止 §4.1 |
| 扇動 = 次の住民が必ず事件 | 対象指定 + カルマ消費 + 噂注入 §4.2 |
| 裁判 fate = kill/spare | death/educate §5 + 制裁つるし上げ §4.3 |
| Chronicle 単一モーダル | 多面履歴ページ §8 |

## 10. 開いている判断 (要確認 / 観戦調整)

- **数値 (観戦調整・env)**: カルマ蓄積レート/扇動・制裁コスト/善性係数 k/イベント発火確率/事件用キャラ生成数。
- **感情の降格**: §3.1 の「感情=AI」を「感情=プログラム」に変える点は破壊的。三分の建付け自体を改訂するか、LLM モードのみ AI 感情を残すオプションにするかは実装時に確定 (既定=プログラム)。
- **月次事件と制裁/扇動裁判の併存**: 同日に月次事件と制裁が重なった場合の優先順位 (制裁を翌日へ送るか並行裁判にするか)。暫定 = 制裁優先・月次事件は遅延。
- **連続犯の継続表現**: 真犯人 (事件用キャラ) が残ったときの翌月デザインへの引き継ぎ粒度。
- **村のルール生成**: テンプレ固定か LLM 種付きか (既定=テンプレ + 月初 LLM が任意で 1 つ足す)。
