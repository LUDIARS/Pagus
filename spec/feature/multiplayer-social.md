# 多人数ソーシャル機能 (v1.2) — 応援 / 村いじり / 裁判参加 / 称号・陣営

> 2026-06-28 起草。2026-07 改定: 裁判ベットを廃止し、裁判は「誰を裁くか」「死刑か教育か」を選ぶ参加 UI に集約する。
> 直接介入は残すが、中心体験は **推しを間接的に洗脳することで村を荒らす** ことに置く。
> 既存資産 (カルマ/善性=`server/player-state.ts`、村のルール=`world.villageRules`、BehaviorRule=`sim/behavior-rules.ts`、裁判=`TermMachine`) の上に **毎 tick LLM を増やさず** 乗せる。

## 0. 方針

- 状態は基本 **server (per-userId)**。sim には最小限のフック (推しの死の検知・村ルール編集・裁判参加記録) だけ足す。
- 接続↔userId は既存 (`hello` + ws-server の `connUser`)。per-connection 送信 (`sendToUser`) も既存。
- 通常介入は 1 日 1 回。使えない日は介入メニュー全体をグレーアウトする。
- 裁判は通常介入メニューとは別枠。裁判中の専用 UI で参加できる。

## 1. 推し指名 (champion) + 弔い (legacy)

### 1.1 推し指名

- `ClientMessage` `{ t:'champion'; targetId; userId? }` — その userId の **推し**を 1 体指定 (再送で差し替え、自分自身の前推しは解除)。
- `PlayerEntry.championId: VillagerId | null` を持つ。
- **推しが生存中はカルマ加速**: `accrue` の加算に推し生存なら `× PAGUS_CHAMPION_KARMA_MULT`(既定1.5)。
- `playerState` に `championId` / `championName` を載せて返す。

### 1.2 弔い (legacy)

- server は snapshot ごとに「前回生存 → 今回 `alive=false`」になった villager を検知する。
- 死んだ villager を**推しにしていたユーザ**へ: カルマ `-PAGUS_CHAMPION_DEATH_PENALTY`(既定20)、`championId` を null にする。
- **弔い = legacy 痕跡**: 死んだ villager に推しがいた場合、村に追悼の `VillageRule` を追加し次の火種にする。

### 1.3 推し経由の間接洗脳

- 直接の扇動/制裁/応援/贈り物は残す。ただし設計の重心は「神が推しを操り、推しの行動が村を崩す」ことに置く。
- プレイヤーは推しへ応援・贈り物・薬物・噂・信仰を集中させ、推しの感情/気質/所持金/関係/情報を歪める。
- 歪んだ推しは日々のルーティーン、恋愛・夫婦関係、事件発火、村長選挙、裁判での態度に影響を及ぼす。
- UI は「推し」「信仰」「LLM脳」「最近の行動」を住民リスト/詳細で見せ、間接操作の結果を追えるようにする。

## 2. しきたり改定

- `world.villageRules` を server 経由で追加/削除する。
- `addRule` はカルマ `PAGUS_RULE_ADD_COST`、`removeRule` は `PAGUS_RULE_REMOVE_COST`。
- しきたりは daily-engine / blackbox の事件設計入力になり、次月以降の火種として残る。

## 3. 裁判参加 (ベット廃止)

- 裁判は 1 日 1 回まで。`World.trialDayKey` で同日多重発生を止める。
- foolish 段階: プレイヤーは **誰を裁くか** を選ぶ。候補は事件関係者/容疑者。
- fate 段階: プレイヤーは **死刑か教育か** を選ぶ。
- プレイヤーが fate 段階で発言したら、住民が 3 言ほど「乗る/乗らない」反応を返し、その後に判決へ進む。
- 裁判が短く終わりすぎないよう、住民が一周する程度の発言を `tenStep` で確保する。
- 裁判中のエラーは検知し、`repairTrialState` で stage/defendant/votes を補正してログに出す。
- `betState` / `BetPool` / 裁判ベット UI は廃止。裁判参加の実績は `trialVotes` として記録する。

## 4. 称号 / 実績 + 二大陣営

### 4.1 実績カウンタ

- `PlayerEntry.stats: { incites; sanctions; cheers; rulesAdded; trialVotes; championDeaths }` をインクリメント。

### 4.2 称号 (titles)

- 称号は**プレイヤー間の最大保持者**に与える動的タイトル (同点は userId 昇順):
  - `破壊神` = incites 最多
  - `審判者` = sanctions 最多
  - `聖人` = cheers 最多
  - `立法者` = rulesAdded 最多
  - `陪審員` = trialVotes 最多
- 0 件の項目は称号を出さない。各ユーザの主称号は最も尖った項目で 1 つ選ぶ。

### 4.3 二大陣営 (善導 vs 扇動)

- `{ t:'faction'; side:'guide'|'incite'; userId? }` で選択。
- 未選択は行動から推定: `cheers + rulesAdded >= incites + sanctions` なら善導、それ以外は扇動。
- client はプレイヤー欄に称号・陣営・スコアボードを表示する。

- **v1.2-B**: §3 裁判参加 + §4 称号・陣営。
- **2026-07 改定**: 裁判ベット削除、裁判専用 UI 化、推し経由の間接洗脳を設計中心に追加。

## 6. env 既定 (観戦調整)

`PAGUS_CHAMPION_KARMA_MULT`=1.5 / `PAGUS_CHAMPION_DEATH_PENALTY`=20 / `PAGUS_RULE_ADD_COST`=15 / `PAGUS_RULE_REMOVE_COST`=25 / `PAGUS_VILLAGE_RULES_MAX`=12。

## 7. 開いた判断

- 弔いの legacy ルール文面: テンプレ固定 (既定) か Haiku 起案か。
- 陣営スコアのシーズン境界 (月 or 任意リセット)。暫定 = 累積。
- 称号のしきい値型 (○件以上) vs 最大保持者型。暫定 = 最大保持者型。
- 間接洗脳の可視化を、信仰値だけで足りるか、専用の「洗脳/依存」状態に分けるか。
